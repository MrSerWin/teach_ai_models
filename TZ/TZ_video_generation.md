# ТЗ: Бесплатная генерация видео взамен Gemini/Veo (для GPU-машины)

**Версия:** 1.0 · **Дата:** 2026-05-26
**Проект-получатель:** реализуется на отдельной машине с NVIDIA GPU.
**Проект-потребитель:** TrashCat (автопостер кото-видео) — забирает готовые ролики.

---

## 1. Контекст и цель

Есть рабочий автопостер `TrashCat`: публикует короткие вертикальные кото-видео
в VK / Instagram / RuTube по расписанию (05:00 / 13:00 / 21:00). Видео ранее
генерировались через Gemini/Veo (браузерная автоматизация Playwright).

**Проблема:** доступ к Veo на аккаунте исчерпан/нестабилен — генерация виснет
на «Generating your video…» и не отдаёт ролик. Браузерный путь хрупкий
(логауты, анти-бот, сломанные чаты, суточные лимиты).

**Цель:** построить **бесплатный, автоматический** генератор видео на машине с
хорошей видеокартой, который production-ready отдаёт 2–3 ролика/сутки в формате,
который без изменений принимает существующий публикатор TrashCat.

**Стиль контента (жёсткое требование):**
- Вирусный, но **family-safe** (для взрослой аудитории, без 18+).
- Котики; часто персонаж «Истер» (мама-кошка с котятами).
- Бытовые сцены, физические/ASMR-эксперименты, fluid/macro-эстетика.
- **Запрещено:** ругательства, оскорбления, обидный контент.

---

## 2. Целевая среда

- ОС: Linux или Windows с **NVIDIA GPU** (CUDA). Рекомендуется **≥24 GB VRAM**
  (RTX 3090 / 4090 / A5000 / A6000). На 12–16 GB — только LTX/квантованные сборки.
- Python 3.10–3.12, CUDA-совместимый PyTorch.
- FFmpeg (для конвертации 16:9 → 9:16).
- Доступ в интернет (скачать веса моделей один раз; для браузерных источников —
  постоянно).

---

## 3. Источники генерации видео (по приоритету)

Реализовать как **pluggable backends** за единым интерфейсом (см. §5). Можно
включать/выключать через конфиг и задавать приоритет/фолбэк.

### Приоритет A — Локальные open-source модели (на GPU). Основной поток.
Безлимит, без вотермарок, без логинов/анти-бота, полностью скриптуются.

| Модель | VRAM | Качество | 9:16 | Длит. | Как запускать | Примечание |
|---|---|---|---|---|---|---|
| **Wan 2.2** (Alibaba) | 24 GB+ (есть 5B/A14B; квант. под меньше) | Лучшее OSS, ~Veo | да | 5–8с | ComfyUI / diffusers | **Рекомендация №1** по качеству |
| **HunyuanVideo** (Tencent) | 24–45 GB (fp8/квант. меньше) | Топ, кинематографично | да | 5с | ComfyUI / diffusers | Тяжёлая, отличная картинка |
| **LTX-2.3** (Lightricks, 22B) | 12 GB (int4) … 42 GB (bf16) | Хорошее, ниже флагманов | да (native) | до 60с | diffusers / ComfyUI / CLI | Быстрая, есть distilled (~8 шагов) |
| **CogVideoX-5B** | 12–24 GB | Среднее | да | ~6с | diffusers | Лёгкий фолбэк |

**Рекомендация:** primary = **Wan 2.2** (качество близко к Veo), fallback =
**LTX-2.3 distilled** (скорость/объём). HunyuanVideo — для «витринных» роликов,
если VRAM позволяет.

**Интеграция локальных моделей:** удобнее всего через **ComfyUI в API-режиме**
(`--listen`, REST `/prompt`) — workflow-граф под каждую модель, программный вызов
с подстановкой промпта; либо напрямую через `diffusers` пайплайны. Оба варианта
дают «настоящий API» без браузера.

### Приоритет B — Бесплатные веб-тарифы через браузерную автоматизацию (Playwright).
Для разнообразия и «топ-качества по запросу». Хрупкие, с лимитами/вотермарками.

| Сервис | Free-лимит/сутки | Качество | 9:16 | Вотермарка | Длит. | Автоматизация |
|---|---|---|---|---|---|---|
| **Seedance 2.0 / Dreamina** (ByteDance) | ~225 общих токенов → 1–2 клипа | Лучшее из веба, ~Veo | да | да | ~5с | 3/5, анти-бот |
| **Kling 3.0** (Kuaishou) | 66 кредитов/день (5с=25, 10с=50) → 2–3 клипа; кредиты можно «фармить» | Топ движение | да | видимая + SynthID; **free = некоммерч.** | 5–10с | 2/5, телефон-верификация |
| **Hailuo / MiniMax 2.3** | стартовый пул (~1000), суточный бонус убран в 2025 | Хорошее движение | да | да | **6с (free)** | 3/5; есть сторонние обёртки (Pollo/Media.io) с своими free-пулами |

**Замечания по веб-источникам:**
- Seedance — лучшее качество, но крошечный пул; держать для hero-клипов.
- Kling — лучшая «фармибельная» квота, НО SynthID + запрет коммерции на free —
  риск для монетизации YouTube; учитывать.
- Hailuo — 6с приемлемо; официальный суточный бонус почти исчез, но сторонние
  обёртки дают свои free-кредиты (можно ротировать).
- ❌ **Sora** — закрыта (апрель 2026). ❌ **Grok Imagine** — free урезан до 480p,
  по сути платный.

### НЕ использовать
Любые «free video API» от реселлеров (PiAPI, Kie.ai, CometAPI, fal.ai) — это
одноразовые триал-кредиты, не возобновляются. Не строить на них поток.

## 4. Функциональные требования (полный pipeline)

Один прогон = одна итерация генерации одного ролика. За сутки — N итераций
(по умолчанию 2–3), запуск по расписанию (cron/launchd/systemd-timer).

```
[1] Получить идею/промпт  →  [2] Сгенерировать видео (backend по приоритету)
   →  [3] Скачать/сохранить РОВНО новое видео  →  [4] Конвертация 16:9→9:16
   →  [5] Сформировать prompt.txt (4 секции)  →  [6] Положить в буфер to_load
   →  [7] Дедуп + quality-gate + лог
```

### [1] Идея/промпт
Два источника (как в TrashCat), в порядке приоритета:
1. **Очередь** `queue.txt` — заранее заготовленные 4-секционные блоки.
2. **Генерация текста LLM** — локальная (Ollama/llama.cpp: Qwen2.5/Llama-3.x) или
   через Gemini text (бесплатно, без видео-режима). Промпт — строго в формате §6,
   стиль из §1. Few-shot из прошлых удачных промптов.

### [2] Генерация видео
- Вызов backend'а из §3 по приоритету; при неудаче/лимите — фолбэк на следующий.
- Veo-промпт = английский, кинематографичный, ≤8с действия.
- Backend возвращает локальный путь к .mp4 (или байты).

### [3] Выбор «правильного» видео — КРИТИЧНО
> Урок из браузерной версии: легко скачать СТАРОЕ видео.
- Для локальных моделей проблемы нет — backend отдаёт именно сгенерированный файл.
- Для браузерных: снять **полный baseline** ВСЕХ существующих видео ДО отправки
  промпта; новое = то, чего не было в baseline; брать **самое нижнее/последнее**
  в ленте; сверять по стабильному ключу (для Veo это был параметр `c=` в URL).
  Никогда не доверять «первому попавшемуся» URL из сети (старые ре-фетчатся при
  скролле). Дедуп по md5 готового файла (см. §7).

### [4] Конвертация 16:9 → 9:16
- В TrashCat есть готовый `video_auto_uploader/convert_to_vertical.py` (blur-метод,
  выход 1080×1920, имя `video.mp4`). Можно переиспользовать as-is или портировать.
- Если backend уже отдаёт 9:16 1080×1920 — конвертация пропускается (проверять
  ориентацию/размер).

### [5] prompt.txt — формат (дословно, 4 секции)
```
Шикарный промпт для генерации:

"<Veo prompt на английском>"

Заголовок для YouTube (99 симв.):

<заголовок, заканчивается #shorts>

Описание к видео (EN/RU):

<строка EN>
<строка RU>

Хештеги: <8–12 хештегов>
```

### [6] Буфер to_load — контракт с публикатором (см. §5)

### [7] Дедуп, quality-gate, лог
- **Quality-gate:** mp4 ≥ 500 KB, длительность ≥ 5с, разрешение вертикальное.
  Битые/маленькие — отбраковка, не попадают в буфер.
- **Дедуп:** md5 готового `video.mp4` сверять с реестром уже выданных
  (`state/produced_hashes.json`). Дубль — отбраковать и перегенерировать.
- **Лог:** JSONL `state/generation_log.jsonl` (ts, источник, idea_title, статус,
  размер, путь).

## 5. Архитектура и интерфейсы

### 5.1 Pluggable backend (единый интерфейс)
```python
class VideoBackend(Protocol):
    name: str
    def is_available(self) -> bool: ...           # квота/доступность
    def generate(self, veo_prompt: str, *, aspect: str = "9:16",
                 duration_s: int = 8) -> Path | None: ...  # путь к .mp4 или None
```
Бэкенды: `WanLocalBackend`, `HunyuanLocalBackend`, `LTXLocalBackend`,
`SeedanceWebBackend`, `KlingWebBackend`, `HailuoWebBackend`.
Оркестратор перебирает по приоритету из конфига до первого успеха.

### 5.2 Контракт ВЫХОДА (стыковка с публикатором TrashCat)
Готовый ролик кладётся папкой в **буфер `to_load/`**:
```
to_load/<slug>_<unixts>/
├── video.mp4      # ОБЯЗАТЕЛЬНО: вертикальное 1080×1920, ≥5с, ≥500 KB
└── prompt.txt     # формат §5 ([5] выше)
```
- `slug` — из заголовка (латиница/цифры/подчёркивания, ≤60 симв.).
- Публикатор сам берёт `video.mp4` и метаданные из `prompt.txt`, публикует,
  затем перемещает папку в `1_published/`.

### 5.3 Передача между машинами (GPU-машина → машина TrashCat)
Публикатор TrashCat читает буфер из ДВУХ путей (fallback-список):
1. `/Users/servin/1_dev/my/ai/autoposters/TrashCat/to_load`
2. `/Volumes/T9/1_dev_flash/Temp/TrashCat/to_load`  ← **общий внешний диск**

Варианты доставки готовых папок:
- **Через общий диск T9** (если GPU-машина его видит) — писать прямо в (2).
- **rsync/scp по расписанию** с GPU-машины в `to_load/` машины TrashCat.
- **Облачная папка** (Syncthing/Dropbox), смонтированная в один из путей.
Рекомендация: rsync по cron (надёжно, без зависимостей).

## 6. Промпт-формат и стиль (для генератора идей)
- Veo-промпт: английский, структура «The Setup / The Action / The Detail /
  The Light / The Sound / Final Shot», кинематографично, ≤8с.
- Заголовок: двуязычный акцент, эмодзи, заканчивается `#shorts`, ≤99 симв.
- Описание: строка EN + строка RU.
- Хештеги: 8–12, тематические (#ai #shorts #cats #asmr #котята #эстетика …).
- Стиль/ограничения — §1. Не повторять сюжеты (few-shot + дедуп идей).

---

## 7. Нефункциональные требования
- **Бесплатно:** только локальные OSS + free веб-тарифы. Никаких платных API.
- **Автоматически:** запуск по расписанию, без ручных шагов. Идемпотентность
  (рестарт не плодит дубли — state-файлы дат/хэшей).
- **Устойчивость:** падение одного backend → фолбэк; недоступность диска/сети →
  пропуск итерации без краха; таймауты на генерацию.
- **Наблюдаемость:** логи + JSONL + (опц.) уведомление в Telegram об итоге прогона.
- **Буфер:** держать ≥ N дней запаса (при 3 публ./день и 2–3 ген./день — ОК).

---

## 8. Приоритеты реализации (MVP → расширение)
1. **MVP:** один локальный backend (**Wan 2.2** через ComfyUI API) +
   генерация идеи (локальный LLM или Gemini text) + конвертация + запись в
   `to_load/` + quality-gate/дедуп. Запуск по cron 2–3×/сутки. rsync в TrashCat.
2. **+ Фолбэк-бэкенды:** LTX-2.3 (скорость), HunyuanVideo (качество).
3. **+ Веб-источники** (Playwright): Seedance → Kling → Hailuo как
   дополнительный/«hero» поток с обработкой лимитов и вотермарок.
4. **+ Автоподбор:** ротация backend'ов по дневным лимитам, метрики качества.

---

## 9. Риски и открытые вопросы
- VRAM целевой машины определит набор моделей (уточнить точную видеокарту).
- Wan 2.2 / Hunyuan требовательны — заложить квантованные сборки/fp8 при <24 GB.
- Веб-источники: анти-бот, вотермарки, SynthID (Kling), некоммерческие лицензии
  free-тарифов — для монетизации YouTube предпочесть локальные OSS (открытые
  лицензии) как основной поток.
- Лицензии моделей под коммерческое использование — проверить (Wan/Hunyuan/LTX
  обычно допускают, но сверить актуальные условия).
- Юр.отметки об ИИ-контенте на площадках (YouTube/Instagram) — учесть при описании.

## 10. Definition of Done
- [ ] Скрипт по расписанию генерирует 2–3 валидных вертикальных ролика/сутки
      полностью без ручного участия.
- [ ] Каждый ролик — гарантированно НОВЫЙ (дедуп по md5), проходит quality-gate.
- [ ] Готовые папки `to_load/<slug>_<ts>/{video.mp4,prompt.txt}` доезжают до
      машины TrashCat и публикуются без правок публикатора.
- [ ] При недоступности основного backend срабатывает фолбэк; сбои логируются,
      процесс не падает.
- [ ] Ноль платных вызовов; ноль ручных шагов в штатном режиме.

### Приложение A. Что переиспользовать из TrashCat
- `video_auto_uploader/convert_to_vertical.py` — конвертация 16:9→9:16 (blur,
  1080×1920, `video.mp4`). Готов к переносу.
- `gemini_fetcher/idea_generator.py` — генерация идеи + формат блока (§6),
  очередь `queue.txt`, few-shot. Логику можно портировать (отвязать от Gemini-UI,
  подключить локальный LLM).
- Формат `prompt.txt` и структура `to_load/` — §5.2 (контракт публикатора).

### Приложение B. Сводная рекомендация
- **Основной поток:** Wan 2.2 (ComfyUI API) на GPU-машине → rsync в `to_load`.
- **Скорость/объём:** LTX-2.3 distilled.
- **Hero-качество по запросу:** HunyuanVideo (локально) или Seedance (веб, вручную).
- **Доп. веб-источники:** Kling/Hailuo через Playwright — опционально, с учётом
  лицензий и вотермарок.
